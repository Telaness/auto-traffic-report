## 1. はじめに

### 1.1 オトレポの位置づけ

「オトレポ」は、HP制作・保守運用先のクライアントサイトについて、Google Analytics 4（GA4）から月次トラフィックを自動取得し、レポートを生成して **メール / LINE** で配信する社内向けWebアプリケーションです。
従来手動で行っていた以下の作業を一括して自動化します。

- GA4でのトラフィック確認
- レポート資料の作成
- クライアントへのメール／LINE配信

### 1.2 主な機能

- クライアント／サイトの登録・管理（複数サイト対応）
- GA4 + Search Consoleからの月次データ自動取得
- AI（Claude）によるトラフィック分析コメントの自動生成
- 標準フォーマットのHTML／PDFレポート生成
- メール／LINE による自動配信（個別／一括／テスト送信）
- 月次自動バッチ処理（毎月1日 8:00 JST）
- 配信ログ・履歴の確認

### 1.3 本書の前提

- 管理者アカウント（ユーザー名・パスワード）が発行済み
- 配信に必要な環境変数（GA4／SMTP／LINE／Anthropic）が設定済み
- クライアントサイトに GA4 が導入され、サービスアカウントに閲覧権限が付与されている
- 利用ブラウザは最新版のChrome／Edge／Safariを推奨

## 2. 事前準備（環境変数・外部サービス設定）

本アプリは複数の外部サービス（Google Cloud / GA4 / Search Console / LINE / SMTP / Anthropic）と連携します。
ここでは **各サービス側でのアカウント・権限・キーの取得手順** から **`.env` への反映方法** までを順を追ってまとめます。
すでに環境変数の値が揃っている場合は [2.8 環境変数への反映と動作確認](#28-環境変数への反映と動作確認) から確認すれば問題ありません。

### 2.1 環境変数の一覧

実装上、以下が `.env` に設定されていないと該当機能が動作しません。**設定** 画面でも設定状況を確認できます（[17. 設定](#17-設定環境変数チェック)）。

| カテゴリ | 環境変数 | 用途 |
|---------|---------|------|
| 認証 | `ADMIN_USERNAME`, `ADMIN_PASSWORD` | 管理画面ログインID／パスワード |
| 認証 | `NEXTAUTH_SECRET`, `AUTH_SECRET` | NextAuth.jsのセッション署名 |
| GA4 | `GOOGLE_SERVICE_ACCOUNT_KEY`（または `GOOGLE_APPLICATION_CREDENTIALS`） | GA4 / Search Console アクセス用サービスアカウント |
| メール | `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | SMTPメール送信 |
| LINE | `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_CHANNEL_SECRET` | LINE Messaging API／Webhook |
| AI | `ANTHROPIC_API_KEY` | AI分析コメント生成 |
| その他 | `ADMIN_EMAIL` | システムアラート送付先 |
| Cron | `CRON_SECRET` | 外部Cron（Vercel等）からの自動バッチ呼び出し認可 |

GA4側ではサービスアカウントに対して **「閲覧者」以上** の権限を、Search Consoleでは対象プロパティに **閲覧権限** を付与してください。

> 環境変数を変更した場合は、サーバを再起動して反映します。

### 2.2 Google Cloud：サービスアカウントの作成

GA4とSearch Consoleからデータを取得するため、Google Cloud上でサービスアカウントを作成し、JSONキーを発行します。
**初期構築時に1回行えばOK**（クライアントごとに作る必要はありません）。

#### 操作手順

1. [Google Cloud Console](https://console.cloud.google.com/) にアクセスし、Googleアカウントでログイン。
2. 上部のプロジェクトセレクタから **新規プロジェクトを作成**（既存プロジェクトを使う場合はスキップ）。
   - プロジェクト名（任意）：例 `auto-traffic-report`
3. 左メニュー **「APIとサービス」 → 「ライブラリ」** から、以下のAPIを **有効化** する：
   - **Google Analytics Data API**（GA4データ取得に必須）
   - **Google Search Console API**（検索パフォーマンス取得に必須）
4. 左メニュー **「IAMと管理」 → 「サービスアカウント」** へ移動。
5. **「サービスアカウントを作成」** をクリック：
   - サービスアカウント名：任意（例：`auto-traffic-report-sa`）
   - サービスアカウントID：自動生成のままでOK
   - 「作成して続行」 → 役割は付与不要（プロジェクトレベルでの権限は不要） → 「完了」
6. 作成したサービスアカウントを開き、**「キー」タブ → 「鍵を追加」 → 「新しい鍵を作成」 → JSON** を選択 → 「作成」。
7. JSONファイルが自動ダウンロードされる。**このファイルは再発行できないため、安全に保管すること**。
8. サービスアカウントの **メールアドレス**（`xxx@xxx.iam.gserviceaccount.com` 形式）を控える。
   - GA4・Search Console側でこのメールアドレスに権限を付与します。

#### 環境変数への設定

JSONファイルの中身を文字列としてそのまま `.env` の `GOOGLE_SERVICE_ACCOUNT_KEY` に設定するか、ファイルパスを `GOOGLE_APPLICATION_CREDENTIALS` に設定します。

```env
# 方法1：JSON文字列を直接設定（改行は\nのままでOK）
GOOGLE_SERVICE_ACCOUNT_KEY='{"type":"service_account","project_id":"...","private_key":"-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n",...}'

# 方法2：ファイルパスを指定（ローカル開発向け）
GOOGLE_APPLICATION_CREDENTIALS=/absolute/path/to/service-account-key.json
```

> **取り扱い注意**：JSONキーは漏洩するとGAデータが第三者に閲覧される可能性があります。
> Gitにコミットしないこと（`.gitignore` に `.env` と `*.json` キーファイルを必ず含める）。

### 2.3 GA4：サービスアカウントへの閲覧権限付与

クライアントの各GA4プロパティに対して、サービスアカウントを「閲覧者」として追加します。
**新規クライアント（サイト）追加のたびに必要** な作業です。

#### 操作手順

1. [Google Analytics](https://analytics.google.com/) にログイン。
2. 対象のアカウント／プロパティを選択。
3. 左下の **歯車アイコン（管理）** をクリック。
4. **「プロパティのアクセス管理」** を開く。
5. 右上の **「+」ボタン → 「ユーザーを追加」** をクリック。
6. メールアドレス欄にサービスアカウントの **メールアドレス**（`xxx@xxx.iam.gserviceaccount.com`）を貼り付け。
7. **「新規ユーザーにメールで通知する」のチェックは外す**（サービスアカウントは受信できないため）。
8. 役割を **「閲覧者」** に設定。
9. **「追加」** をクリック。

#### GA4プロパティIDの確認

レポート登録時に必要な「GA4プロパティID」は、管理画面の **「プロパティの設定」** または **「プロパティの詳細」** で確認できます。
- 形式：`123456789`（数字のみ）または `properties/123456789`
- アプリ側ではどちらの形式でも受け付けます（内部で正規化）。

> **クライアントが自社GA4を持っている場合**：クライアント側のGA4管理者にサービスアカウントのメールアドレスを伝え、「閲覧者」権限で追加してもらう必要があります。
> 依頼テンプレートを用意しておくと運用がスムーズです。

### 2.4 Search Console：サービスアカウントへの閲覧権限付与

各サイトのSearch Consoleプロパティに、サービスアカウントをユーザー追加します。
**GA4とは別の権限管理** です。GA4で権限付与済みでも、Search Console側で追加が必要です。

#### 操作手順

1. [Google Search Console](https://search.google.com/search-console) にログイン。
2. 上部のプロパティセレクタから対象のプロパティを選択。
3. 左メニュー下部の **「設定」** をクリック。
4. **「ユーザーと権限」** を開く。
5. **「ユーザーを追加」** をクリック。
6. メールアドレス欄にサービスアカウントの **メールアドレス** を貼り付け。
7. 権限を **「フル」** または **「制限付き」** に設定。
   - データ閲覧のみであれば **「制限付き」** で十分。
8. **「追加」** をクリック。

#### プロパティ種別の注意

Search Consoleには2種類のプロパティがあります。
- **ドメインプロパティ**（`example.com` 全体）
- **URLプレフィックスプロパティ**（`https://www.example.com/` のみ）

オトレポに登録するサイトURLと **対応するプロパティ** に権限を付与してください。両方登録されている場合はどちらでもOKです。

> Search Consoleが未設定のサイトは、検索パフォーマンスデータが空欄になります（レポート生成自体は可能）。

### 2.5 LINE Messaging API：チャンネル作成とトークン発行

LINEで配信するための公式アカウント／チャネルを作成し、アクセストークンとシークレットを取得します。
**初期構築時に1回行えばOK**。

#### 操作手順

1. [LINE Developers Console](https://developers.line.biz/console/) にアクセスし、LINEアカウントでログイン。
2. **プロバイダー** を作成（既存があればスキップ）。
   - プロバイダー名：例 `Telaness`
3. 作成したプロバイダー内で **「新規チャネル作成」 → 「Messaging API」** を選択。
4. 必要事項を入力（チャネル名・説明・カテゴリ等）して作成。
5. 作成後、チャネル設定画面で以下を取得：
   - **「チャネル基本設定」タブ → 「チャネルシークレット」** をコピー → `LINE_CHANNEL_SECRET` に設定。
   - **「Messaging API設定」タブ → 「チャネルアクセストークン（長期）」** で **「発行」** をクリック → コピー → `LINE_CHANNEL_ACCESS_TOKEN` に設定。
6. **Webhook設定**（友だち追加・グループ参加時に自動で `LineTarget` へ登録するため必須）：
   - 「Messaging API設定」タブ → **「Webhook URL」** に `https://（管理画面ドメイン）/api/webhook/line` を入力 → 「更新」。
   - **「Webhookの利用」** を **ON** に切り替え。
   - **「検証」** をクリックし、Successと表示されればOK。
7. **「応答メッセージ」** は **OFF** 推奨（テンプレ自動返信を止めるため）。
   - LINE Official Account Manager から「応答設定」→「応答メッセージ」をOFF。
8. **「あいさつメッセージ」** は任意（友だち追加時の挨拶を出したい場合のみON）。

#### 公式アカウントの友だち追加（運用開始前）

- LINE公式アカウントの **QRコード** または **ID検索** で、配信対象のクライアント／グループから友だち追加してもらいます。
- 追加されると、Webhook経由で `LineTarget` テーブルに自動登録されます（[9.1](#91-line送信先の取得経路) 参照）。
- グループ配信の場合は、**公式アカウントを当該グループに招待** してもらう必要があります。

> **再発行が必要なケース**：チャネルアクセストークンが漏洩した場合や、長期トークンの再発行ボタンを押した場合は、新しいトークンを `.env` に再設定してサーバ再起動が必要です。

### 2.6 SMTP：メール送信の準備

メール配信用のSMTPサーバー認証情報を準備します。
Gmail（Google Workspace含む）を使う場合は **アプリパスワード** が必要です（通常のパスワードでは認証できません）。

#### Gmail / Google Workspace を使う場合

1. 送信元として使うGoogleアカウントで **2段階認証** を有効化（[Googleアカウント設定](https://myaccount.google.com/security)）。
2. **「セキュリティ」 → 「アプリパスワード」** を開く。
   - 2段階認証ONでないと表示されません。
3. アプリ名を入力（例：`auto-traffic-report`）→ 「作成」。
4. 16桁のパスワードが表示されるのでコピー → `SMTP_PASS` に設定。
5. `.env` に以下を設定：

```env
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-account@gmail.com
SMTP_PASS=（手順4でコピーしたアプリパスワード／空白なし）
SMTP_FROM="オトレポ <your-account@gmail.com>"
```

#### その他のSMTPサーバーを使う場合

各サービスの公式手順に従ってSMTP情報を取得し、上記と同じ環境変数に設定してください。代表例：

| サービス | SMTP_HOST | SMTP_PORT | SMTP_USER | SMTP_PASS |
|---------|-----------|-----------|-----------|-----------|
| SendGrid | `smtp.sendgrid.net` | `587` | `apikey`（固定文字列） | 発行したAPIキー |
| Amazon SES | リージョン依存（例：`email-smtp.ap-northeast-1.amazonaws.com`） | `587` | SMTP認証情報のユーザー名 | SMTP認証情報のパスワード |
| Mailgun | `smtp.mailgun.org` | `587` | ドメイン用SMTPユーザー | ドメイン用SMTPパスワード |

> **送信元ドメイン**：`SMTP_FROM` のドメインに対して、SPF / DKIM / DMARC を整備しておくと到達率が改善します。
> Gmailの場合は通常自動で整っていますが、独自ドメインを `SMTP_FROM` に使う場合はDNS設定の確認が必要です。

### 2.7 Anthropic：APIキーの発行

AI分析コメント生成用のAPIキーを発行します。**初期構築時に1回行えばOK**。

#### 操作手順

1. [Anthropic Console](https://console.anthropic.com/) にアクセスし、サインアップまたはログイン。
2. 左メニュー **「API Keys」** を開く。
3. **「Create Key」** をクリック。
4. キー名を入力（例：`auto-traffic-report-prod`）し、作成。
5. 表示されたキー（`sk-ant-...` で始まる文字列）をコピー → `.env` の `ANTHROPIC_API_KEY` に設定。
   - キーは作成時にしか表示されません。**コピー漏れ時は再作成が必要**。
6. 必要に応じて、Anthropic Console上で **使用量上限（Spend limit）** を設定。

> **取り扱い注意**：APIキーは漏洩すると不正利用される可能性があります。
> Gitにコミットしない、ログに出力しない、共有しないこと。
> 漏洩した場合はAnthropic Console上で **失効（Revoke）** し、新しいキーを発行してください。

### 2.8 環境変数への反映と動作確認

#### `.env` の作成

リポジトリ直下に `.env` ファイルを作成し、これまでに取得した値を設定します。

```env
# ===== 認証 =====
ADMIN_USERNAME=admin
ADMIN_PASSWORD=（任意の強固なパスワード）
NEXTAUTH_SECRET=（openssl rand -base64 32 などで生成）
AUTH_SECRET=（NEXTAUTH_SECRETと同じ値で可）

# ===== Google（GA4 / Search Console）=====
GOOGLE_SERVICE_ACCOUNT_KEY={"type":"service_account",...}

# ===== SMTPメール =====
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-account@gmail.com
SMTP_PASS=xxxxxxxxxxxxxxxx
SMTP_FROM="オトレポ <your-account@gmail.com>"

# ===== LINE Messaging API =====
LINE_CHANNEL_ACCESS_TOKEN=...
LINE_CHANNEL_SECRET=...

# ===== AI（Claude）=====
ANTHROPIC_API_KEY=sk-ant-...

# ===== その他 =====
ADMIN_EMAIL=admin@example.com
CRON_SECRET=（openssl rand -hex 32 などで生成）
```

#### 反映方法

| 環境 | 手順 |
|------|------|
| 開発環境 | `.env` を編集後、`pnpm dev` を再起動 |
| 本番環境（Vercel等） | プロジェクトの **環境変数設定画面** に同じ値を登録 → 再デプロイ |

#### 動作確認の流れ

1. アプリにログインし、`/settings` で各環境変数の **設定状況** を確認（[17. 設定](#17-設定環境変数チェック)）。
2. テストクライアントを作成 → `/batch` の **テスト送信** でメール／LINEの疎通を確認。
3. **手動レポート生成**（[10. 手動レポート生成](#10-手動レポート生成)）でGA4／Search Consoleからのデータ取得を確認。
4. PDFダウンロードでAI分析コメントが生成されているか確認。

#### よくあるトラブル

| 症状 | 主な原因 | 対処 |
|------|---------|------|
| `/settings` で「未設定」表示 | `.env` の値が読み込まれていない | サーバ完全再起動／本番環境では再デプロイ |
| GA4から `403 Permission denied` | 対象プロパティへのサービスアカウント追加漏れ | [2.3](#23-ga4サービスアカウントへの閲覧権限付与) を再実施 |
| Search Consoleから `User does not have sufficient permission` | プロパティへの追加漏れ／プロパティ種別不一致 | [2.4](#24-search-consoleサービスアカウントへの閲覧権限付与) を再実施 |
| LINE Webhookが `Invalid signature` で失敗 | `LINE_CHANNEL_SECRET` の不一致 | チャネル基本設定から再コピーして再設定 |
| LINE配信が `Authentication failed` | アクセストークン期限切れ／誤り | LINE Developersで再発行して再設定 |
| メール送信が認証エラー | Gmailで通常パスワードを使っている | アプリパスワードを発行して `SMTP_PASS` に設定 |
| AI分析コメントが空 | `ANTHROPIC_API_KEY` 未設定／無効 | キーを再発行して再設定 |

## 3. ログインとセッション

### 3.1 ログイン手順

1. ブラウザで `https://（管理画面URL）` にアクセス。未認証の場合は `/login` にリダイレクトされます。
2. **ユーザー名** と **パスワード** を入力し、「ログイン」をクリック。
3. 認証成功で **ダッシュボード（`/dashboard`）** に遷移します。

### 3.2 認証とアクセス制御

- 認証は NextAuth.js（Credentials Provider）＋JWTセッションを使用。
- ログイン情報は環境変数 `ADMIN_USERNAME` / `ADMIN_PASSWORD` と照合されます。
- ログイン以外の管理画面ページ（`/dashboard`、`/clients`、`/reports`、`/batch`、`/settings`）はすべて認証必須です。
- 以下のエンドポイントは認証不要です（別の方式で保護）:
  - `/api/auth/...`（NextAuth）
  - `/api/webhook/...`（LINE署名検証で保護）
  - `/api/batch/cron`（`CRON_SECRET` で保護）
  - `/api/reports/[id]/pdf`（短期有効トークンで保護）

### 3.3 ログイン失敗時のレート制限

- 同一 IP × ユーザー名の組合せで **5回連続失敗** すると **15分ロック** されます。
- ロック中はフォーム入力が無効化され、解除までの分数が表示されます。
- 失敗時には残り試行回数（例：「残り3回」）が表示されます。

### 3.4 ログアウト

- 画面右上の **「ログアウト」** ボタンをクリックすると、`/login` に戻ります。

## 9. LINE送信先の管理

LINE送信先は、`LineTarget` テーブルで一元管理されます。1クライアントに **複数の送信先**（グループ／個人）を紐づけ可能です。

### 9.1 LINE送信先の取得経路

1. **公式アカウントを友だち追加** → Webhook 経由で個人ユーザーが自動登録
2. **公式アカウントをグループに招待** → Webhook 経由でグループが自動登録
3. **手動登録** → 管理画面から LINE ID を直接入力（種別：個人 or グループ）

> Webhook（`/api/webhook/line`）は LINE Channel Secret による署名検証で保護されています。

### 9.2 送信先の紐づけ（既存から選択）

クライアント新規登録／編集時に、

1. 「LINE送信先」ラベル横の **「追加」** ボタンをクリック。
2. 「LINE送信先一覧（未紐づけ）」がオーバーレイ表示されます。
3. フィルタタブで「すべて／個人／グループ」を切替可能。
4. 紐づけたい送信先の **「紐づける」** をクリック。
5. クライアント詳細画面では即時、新規登録画面では登録ボタン押下時に確定します。

### 9.3 送信先の紐づけ（手動登録）

LINEの友だち追加が事前に済んでいない、もしくはAPIで取得できないIDを登録する場合：

1. **「手動登録」** ボタンをクリック。
2. **LINE ID**（例：`U1234abcd...`、`C1234abcd...`）と **種別**（個人／グループ）を入力。
3. **「登録」** をクリック。
4. 登録時にLINE APIから displayName / groupName の取得を試行します。

### 9.4 送信先の紐づけ解除

- クライアント詳細・編集モードで、各送信先行の **「解除」** ボタンをクリック。
- 確認ダイアログで承認すると、LineTarget の `clientId` のみが解除されます（送信先レコード自体は残ります）。

### 9.5 送信先の自動更新

- 友だち追加（follow）→ 個人として `isActive=true` で登録
- ブロック（unfollow）→ `isActive=false` に更新（紐づけは保持）
- グループ参加（join）→ グループとして `isActive=true` で登録
- グループ退出（leave）→ `isActive=false`

ブロックされた送信先には配信されません。再追加されると自動的に再有効化されます。

## 10. 手動レポート生成

サイト一覧の **「レポート生成」** ボタンから、任意期間でレポートを生成できます。

### 10.1 操作手順

1. クライアント詳細画面 → 対象サイト行の **「レポート生成」** をクリック。
2. インライン展開された入力欄で **開始日 / 終了日** を入力。
3. **「生成」** ボタンをクリック。
4. 生成完了後、自動で `/reports/[id]` に遷移します。

### 10.2 入力チェック

- 開始日・終了日は必須。未入力時は警告アラート。
- 開始日 > 終了日はNG（警告アラート）。

### 10.3 生成中に行われる処理

1. GA4から指定期間の主要メトリクスと詳細データ（地域・流入元・デバイス・ブラウザ）を取得
2. 同期間長の **直前期間** のGA4データを取得（前期比用）
3. Search Console から検索パフォーマンスを取得（当期間・前期間）
4. AI（Claude）でトラフィック分析コメントを生成
5. `Report` レコードを `status = generated` で作成
6. 結果ID を返却

> 1サイトあたりの目標生成時間は30秒以内（要件 NFR-001）。

## 13. レポート出力・送信（バッチ管理）

`/batch` は、月次バッチ配信のメイン管理画面です。配信登録、自動実行ON/OFF、一括／個別の即時実行が集約されています。

### 13.1 画面上部のヘッダー操作

| ボタン／要素 | 動作 |
|-------------|------|
| 毎月自動実行トグル | ON/OFFで自動配信のスケジューラを切替 |
| **一括バッチ実行** | 全登録を対象に確認ダイアログ → 実行 |
| **個別送信** | 1クライアント＋任意サイトを選んで送信 |
| **新規登録** | 配信登録の追加フォームを開閉 |

### 13.2 配信登録（バッチ Subscriptions）

#### 新規登録

1. **「新規登録」** をクリック。
2. **クライアント** をプルダウンから選択（バッチ未登録のクライアントのみ表示）。
3. **配信チャネル** を選択（メール／LINE／メール+LINE）。
4. **「登録」** で確定。

#### 一覧の項目

| 項目 | 内容 |
|------|------|
| クライアント名 | 登録対象 |
| 配信チャネル | バッチ実行時のチャネル |
| ステータス | 有効／無効（バッチ対象に含むかどうか） |
| 一括除外 | 「対象」「除外中」をクリックでトグル |
| 登録日 | 登録日時 |
| 操作 | テスト送信／編集／停止-有効化／解除 |

#### 各操作の意味

| 操作 | 詳細 |
|------|------|
| テスト送信 | チャネルごとに即時テスト配信。配信ログには記録されず、結果のみ画面に表示 |
| 編集 | 配信チャネルの変更（保存／戻すで確定／取消） |
| 停止 / 有効化 | `isActive` をトグル。停止中はバッチ対象から除外 |
| 解除 | 配信登録を完全に削除（クライアント本体は残る） |
| 「対象」/「除外中」バッジ | `excludeFromBatch` をトグル。除外中は **一括バッチに含まれない** が、個別送信は可 |

### 13.3 一括バッチ実行

#### 操作手順

1. **「一括バッチ実行」** をクリック → 確認ダイアログが開きます。
2. ダイアログ内に **対象一覧** が表示されます（顧客名・サイト・送信方法）。
3. **レポート期間** を選択：

   | タイプ | 内容 |
   |-------|------|
   | 先月（既定） | 自動算出：前月1日〜前月末日 |
   | 月指定 | 任意の年月（その月の1日〜末日） |
   | 日付指定 | 任意の開始日〜終了日 |

4. 右下の **「N件を実行」** をクリック。
5. 完了後、合計／成功／失敗件数のサマリーがアラートで表示されます。

#### 対象算出ロジック

以下を **すべて満たすサイト** が対象になります（`MonthlyBatchSubscription` 単位）。

- `clients.is_active = true`
- `monthly_batch_subscriptions.is_active = true`
- `monthly_batch_subscriptions.exclude_from_batch = false`
- `sites.is_active = true`
- `sites.report_start_date <= 当月1日`

### 13.4 個別送信

#### 操作手順

1. **「個別送信」** をクリック → モーダルが開きます。
2. **顧客** をプルダウンから選択（有効なバッチ登録のみ）。
3. **送信対象サイト**：
   - 紐づくサイトのチェックリストが表示されます。
   - 「全選択／全解除」ボタンで一括切替可能。
   - 1つ以上のサイトを選択しないと「実行」ボタンは無効。
4. **レポート期間** を選択（先月／月指定／日付指定）。
5. **「実行」** をクリック。

#### 個別送信の特徴

- 期間指定なしで実行すると、**先月分** が対象。
- バッチ登録上の「除外中」フラグの影響を受けません。
- 送信先のチャネルは登録上の `deliveryChannel`（メール／LINE／両方）に従います。

### 14.1 個別レポートのPDF取得

`/reports/[id]` の **「PDFダウンロード」** ボタンから取得します。

### 14.2 全クライアントの前月分一括ダウンロード

`/reports` の **「前月レポート一括DL」** から取得。

- 検索パフォーマンス（クリック／インプレッション／順位／キーワード）

## 15. 自動配信スケジューラ

### 15.1 トグルでON/OFF

`/batch` 画面の左上「毎月自動実行」トグルで切替できます。

- ON時：`auto_batch_enabled = true` を `system_settings` テーブルに保存
- OFF時：`false` を保存（実行はスキップされる）

### 15.2 起動タイミング

- アプリ内蔵のスケジューラ：**毎月1日 8:00 JST** に `runMonthlyBatch()` を実行
- 外部Cron（`/api/batch/cron`）：`Authorization: Bearer ${CRON_SECRET}` で起動可能。トグルが OFF の場合はスキップ。

### 15.3 自動実行されない条件

- `auto_batch_enabled` が `false`
- 該当配信登録の `isActive = false`
- 該当配信登録の `excludeFromBatch = true`
- 該当クライアントが無効（`isActive = false`）
- サイトが無効、または `reportStartDate` が当月1日より後

### 15.4 失敗時のリトライ

- 配信失敗ジョブは内部で最大3回までリトライされます（NFR-012）。
- リトライ後も失敗した場合は `DeliveryLog` に `status = failed` で記録され、ダッシュボードに表示されます。

## 16. テスト送信

### 16.1 用途

- 新規クライアントの初期チェック
- メール／LINE設定変更後の動作確認
- 配信不能の原因切り分け

### 16.2 操作手順

1. `/batch` の対象配信登録行の **「テスト送信」** をクリック。
2. 内部で：
   - メールチャネルなら：`【テスト送信】月次トラフィックレポート - クライアント名` の件名で固定文面のメールを送信
   - LINEチャネルなら：紐づけられた **すべての送信先** にテストメッセージを送信（紐づけがない場合はエラー）
3. 結果がチャネル別／送信先別にアラート表示されます。

### 16.3 テスト送信時の注意

- 実際のレポートは含まれません（あくまで疎通確認）。
- 配信ログ（`DeliveryLog`）には記録されません。
- 一部失敗があっても他チャネルは続行されます。

## 17. 設定（環境変数チェック）

`/settings` で、各サービスの設定状況を確認できます。

### 17.1 表示項目

| 項目 | 必要な環境変数 | 「未設定」のときの挙動 |
|------|----------------|------------------------|

- 管理画面では値を直接編集できません（読み取り専用）。
- サーバ上の `.env` を編集 → サーバ再起動で反映。

## 18. 典型的な業務フロー

### 18.1 ［初期セットアップ］新規クライアントを月次配信に乗せる

1. **クライアント一覧 → 新規登録**
   - 会社名／配信チャネル／メール／LINE送信先を登録。
2. **クライアント詳細 → サイト追加**
   - サイト名／URL／GA4プロパティID／レポート開始日を登録。
3. **レポート出力・送信 → 新規登録**
   - 該当クライアントをバッチ配信に追加。
4. **テスト送信** で疎通確認。
5. **毎月自動実行トグル** が ON であることを確認 → 翌月1日 8:00 JST から自動配信開始。

### 18.2 ［運用］過去月のレポートを再送・確認したい

- 単発で送信したい：**レポート出力・送信 → 個別送信** で「月指定」または「日付指定」を選び実行。
- 中身だけ確認したい：**出力レポート履歴 → 詳細** から閲覧、または **PDFダウンロード**。
- ファイルだけ取得したい：**出力レポート履歴（`/reports`）→ 前月レポート一括DL**、または個別レポートの **PDFダウンロード**。

### 18.3 ［運用］今月だけ自動配信を見送りたい

- 該当バッチ登録の「対象」バッジをクリックして **「除外中」** に切替。
- 翌月以降に戻す場合は再度クリックで「対象」に戻します。
- 完全に止めたい場合は **「停止」**、配信不要なら **「解除」**。

### 18.4 ［運用］LINEグループをクライアントに紐づける

1. 公式アカウントを当該グループに招待してもらう（社内 → クライアント側に依頼）。
2. Webhookで自動的にグループが `LineTarget` に登録される。
3. クライアント詳細画面 → 編集 → LINE送信先「追加」 → 該当グループを選んで紐づけ。
4. テスト送信で受信確認。

### 18.5 ［運用］クライアントを完全終了させる

1. クライアント詳細から **すべてのサイトを削除**。
2. レポート出力・送信から該当登録を **解除**。
3. クライアント詳細から **削除（赤）** を実行。
   - サイトが残っていると押下できないので、必ず先にサイト削除を完了させる。

### 18.6 ［運用］過去レポートをまとめて納品したい

- **`/reports` → 前月レポート一括DL**（前月分のみ・全クライアント）
- 個別レポートは **`/reports/[id]` → PDFダウンロード**

## 19. 配信失敗時の対処

### 19.1 失敗の確認

- **ダッシュボード**：直近30件の失敗ログを一覧表示。
- **レポート詳細 → 配信ログ**：チャネル別の失敗内容・リトライ回数。

### 19.2 メール失敗時のチェック項目

| 症状 | 主な原因 | 対処 |
|------|---------|------|
| 認証エラー | `SMTP_USER` / `SMTP_PASS` の誤り | 環境変数を再確認・再起動 |
| 接続エラー | `SMTP_HOST` / `SMTP_PORT` の誤り | サーバ側の値を確認 |
| 受信側拒否 | 宛先メールアドレスの誤り、迷惑メール扱い | クライアント情報を修正、SPF/DKIM/DMARC確認 |
| 送信元拒否 | `SMTP_FROM` ドメイン不一致 | 設定ドメインで送信できるかメールサーバ側で確認 |

### 19.3 LINE失敗時のチェック項目

| 症状 | 主な原因 | 対処 |
|------|---------|------|
| Invalid signature | チャンネルシークレット不一致 | `LINE_CHANNEL_SECRET` を再確認 |
| Authentication failed | アクセストークン期限切れ／誤り | `LINE_CHANNEL_ACCESS_TOKEN` を再発行・再設定 |
| The user has blocked... | 個別ユーザーがブロック | 紐づけ解除、別の送信先を案内 |
| Group/Room not found | グループから退出済み | グループに再招待してもらい、再紐づけ |

### 19.4 GA4取得失敗時

- サービスアカウントが対象 GA4 プロパティに **「閲覧者」以上で追加されているか** を確認。
- プロパティIDが `properties/...` または数値で正しいか確認。
- データが存在しない期間（GA4 導入前）を指定していないか確認。

### 19.5 再送方法

- 個別送信からチャネルを変更せず、対象期間を指定して再実行。
- もしくはテスト送信で疎通確認後、もう一度個別／一括バッチ実行。

## 21. 用語集

| 用語 | 説明 |
|------|------|
| **クライアント** | レポート配信先となる企業（顧客） |
| **サイト** | クライアントが運用するWebサイト。1クライアントに複数登録可能 |
| **GA4プロパティID** | Google Analytics 4 の対象プロパティID（`properties/...`） |
| **レポート開始日** | サイトごとの「最初に対象とする日」。これより前の月は自動配信対象外 |
| **配信チャネル** | レポートの届け方。`email` / `line` / `both` |
| **バッチ配信登録** | 月次自動配信の対象に含めるためのクライアント単位の設定 |

| **DeliveryLog** | 配信履歴のレコード。チャネル別に成功／失敗が残る |
| **AI分析** | Claude APIによるトラフィック評価コメント。レポートPDFに同梱 |

## 22. FAQ

**Q1. ログイン情報を忘れた**
A. 環境変数 `ADMIN_USERNAME` / `ADMIN_PASSWORD` を確認し、必要に応じて変更します。

**Q2. ロックアウトを即時解除したい**
A. サーバ再起動でメモリ上のレート制限はクリアされます（運用環境では推奨されません）。

**Q3. 月次自動バッチが動いていないように見える**
A. ① 自動実行トグルがONか確認。② サーバが起動中か確認（インスタンス停止中は cron が走らない）。③ Vercel等の外部Cronを使用する場合は `CRON_SECRET` の一致を確認。

**Q4. 一括バッチ実行と「前月レポート一括DL」は何が違う？**
A.
- **一括バッチ実行**：未生成分も生成 → 配信。実際の送信を伴う。
- **前月レポート一括DL**：既に生成済みの前月レポートを **PDFのZIP** で取得（送信なし）。

**Q5. PDFが文字化けする／真っ白**
A. Puppeteerの日本語フォント／PDF生成環境を確認。`puppeteer-core` のChromiumが取得できているか、ホストにOSフォントがあるか。

**Q6. 過去レポートの数値を後から修正したい**
A. レポートは生成スナップショットです。再生成は同期間で再実行することで上書きされます（同月で複数生成すると履歴が増える点に注意）。

**Q7. 日次や週次レポートはできる？**
A. 月次が標準ですが、`個別送信` で「日付指定」を使えば任意期間のレポートを生成・配信できます。自動スケジューリングは月次のみです。

**Q8. クライアントが管理画面にログインすることは？**
A. 当アプリは管理者専用です。クライアント向けセルフサービスポータルは提供されません（要件 FR-072）。

新規クライアントの追加時は **「クライアント一覧 → クライアント詳細 → レポート出力・送信」** の順で設定するのが基本フローです。
